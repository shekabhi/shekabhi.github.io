How I work

Things I've come to believe.

Each of these cost me something to learn.

  1. If you can't upgrade it, you can't secure it.

    A fix that needs a full platform release isn't a fix yet. Upgrade paths are a security feature, so I design them first.

  2. Fail loudly at startup, not quietly in production.

    A clear error before the first request is worth more than a stack trace at 2 a.m. Validate configuration early and say exactly what to change.

  3. Make the safe path the easy path.

    People adopt security when it's the default and costs them nothing. If the secure setup needs a 12-step guide, the design isn't finished.

  4. Keep the hot path boring.

    Anything that can happen later should. Alerting, analytics and audit trails go on a queue; the request gets only what it needs to return.

  5. Logs are a feature, and they need an owner.

    Logging nobody manages eventually fills a disk. Rollover, retention and useful context get designed like any other feature.

  6. Design for the next consumer, even a non-human one.

    Yesterday it was another team, today it's an AI agent. Clear contracts and scoped access work for both.
